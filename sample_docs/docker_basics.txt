Docker packages an application and its dependencies into an image. An image is a read-only template made of stacked layers. A container is a running instance of an image. You can start many containers from the same image, and each gets its own writable layer that is discarded when the container is removed.

An image is described by a Dockerfile. The FROM instruction picks the base image, COPY adds files, RUN executes a command during the build, and CMD or ENTRYPOINT defines what runs when the container starts. Each instruction creates a layer, and Docker caches layers, so putting rarely changing steps like installing dependencies before frequently changing steps like copying source code makes rebuilds faster. A multi-stage build uses one stage to compile and a smaller final stage to ship, which keeps the final image small.

Containers are temporary by design. Data written inside a container is lost when it is removed unless you use a volume, which stores data on the host outside the container lifecycle. Port mapping connects a host port to a container port using the format host:container. For example, mapping 8080:80 makes a service listening on port 80 in the container reachable on port 8080 of the host.

Image tags identify versions. The latest tag is just a label that moves over time, so it can change without warning. Pinning a specific version tag makes builds reproducible. A .dockerignore file keeps unneeded files, such as virtual environments and secrets, out of the build. Docker Compose lets you define and start several related containers, such as an app and its database, from a single YAML file.
